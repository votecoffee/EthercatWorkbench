# EtherCAT Workbench

Windows x64 Rust desktop application and headless CLI for EtherCAT MainDevice bench commissioning, SAFEOP input inspection, PDO decoding and CSV capture.

For the current decisions, evidence limits and retained artifacts, start with the [research brief](docs/research-brief.md).

## Install

Extract the portable ZIP. Launch `ethercat-workbench.exe` for the GUI or use `ethercat-workbench-cli.exe` from PowerShell. Offline mode runs with no EtherCAT hardware. Live mode uses the separately installed x64 [Npcap runtime](https://npcap.com/#download), an Ethernet NIC connected to an isolated bench, and access permitted by the Npcap driver policy.

Start with the [operations guide](docs/operations.md) for ESI/manual setup, CLI and hardware boundaries. Developers and future chats can use [AGENTS.md](AGENTS.md) and the [development guide](docs/development.md). Run `powershell -File tools/install-skill.ps1` to install the bundled [EtherCAT Workbench skill](skills/ethercat-workbench/SKILL.md) for future Codex chats, bound to this extracted/source root; modified or unowned installed files are preserved.

To build from source, install Rust 1.92 or later, the MSVC x64 toolchain and Windows SDK, and download the Npcap SDK. Keep the SDK and vendor ESI XML in ignored `.local/`. Set the x64 library directory for the build.

```powershell
$env:LIBPCAP_LIBDIR = (Resolve-Path .local/vendor/npcap/Lib/x64).Path
cargo build --locked --release --target x86_64-pc-windows-msvc
```

## Usage

The desktop uses **Device, Inputs, Outputs, Logging, Mappings, Integration, Diagnostics** tabs, matching the EthernetIP Workbench workflow, plus **Review** for saved captures. **Connect…**, **Profiles…**, **Record CSV…** and **Stop and flush** stay in the header. Start in **Device → Use offline demo**, choose logging, then **Connect… → Offline fixtures**. Raw payloads and advanced settings expand separately. See the [desktop workflow guide](docs/desktop-workspace.md) for the complete navigation and bench-review boundaries.

From the unpacked package, create a local directory for profiles and captures. Choose the bundled synthetic profile in the GUI or use the commands below.

```powershell
New-Item -ItemType Directory -Force .local | Out-Null
.\ethercat-workbench.exe --profile samples/synthetic.json
.\ethercat-workbench-cli.exe run samples/synthetic.json --seconds 4 --csv .local/synthetic.csv
.\ethercat-workbench-cli.exe run samples/virtual.json --backend virtual --seconds 2 --csv .local/virtual.csv
.\ethercat-workbench-cli.exe run samples/virtual-sii.json --backend virtual --virtual-model sii --seconds 2 --csv .local/virtual-sii.csv
.\ethercat-workbench-cli.exe decode samples/synthetic.json "04 00 00 00 00 00 80 3F"
.\ethercat-workbench-cli.exe decode samples/synthetic.json "FE FF" --rx
.\ethercat-workbench-cli.exe esi-list samples/synthetic.esi.xml
.\ethercat-workbench-cli.exe esi-import samples/synthetic.esi.xml --device 0 --out .local/imported.json
.\ethercat-workbench-cli.exe verify-pdo .local/imported.json samples/synthetic-pdo.json
.\ethercat-workbench-cli.exe run samples/synthetic.json --backend replay --replay samples/synthetic-replay.json --seconds 2 --csv .local/replayed.csv
```

Run `check-runtime --out .local/host-prerequisites.json` for a [read-only host check](docs/runtime-check.md) of installed Npcap DLL headers/file versions, driver-service state and the recorded AdminOnly option. Capture access stays unprobed; this command performs no NIC enumeration or bus exchange. Missing/unknown observations remain visible and exports preserve existing files.

The ESI reader accepts UTF-8/UTF-16 and lists devices by vendor, product and revision. Headless import now accepts a unique exact `--identity VENDOR/PRODUCT/REVISION` or a zero-based `--device` index; combine them to reject an index whose identity differs. Ambiguous identity matches require an explicit index. See [exact selection](docs/pdo-selection.md#select-an-exact-esi-device) for examples and bounds. It retains a PDO catalog, including candidates without a default `Sm` assignment. Default choices follow the ESI assignments. It sorts the built image by SyncManager and preserves chosen PDO order, padding and byte alignment between SyncManagers. It records the ESI basename, hash, identity and field sources. The editable bit offsets and lengths are Workbench decoding settings. Use a new profile path to save edits. Select TxPDO fields for CSV and stage RxPDO hex with the expected image length. For aligned numeric fields, transforms apply in the order swap bytes in each 16-bit word, reverse the 16-bit words, then interpret endian order. Bit fields number bit 0 as the least-significant bit of the first byte.

PDO catalog choices can be edited in the GUI before building an imported profile and after reloading a saved profile. Choose candidates, set their SyncManagers and adjust order within a SyncManager, then rebuild the offline fields. Rebuilding clears staged RxPDO bytes. Mandatory selections, exclusions, duplicate choices and mixed Tx/Rx assignments on one SyncManager are checked. Virtual and module-dependent PDOs require further implementation. Choice changes mark their direction's fields as overrides. The separate decoder editor remains available; detach the ESI selection to change image lengths independently.

```powershell
.\ethercat-workbench-cli.exe esi-list samples/pdo-choices.esi.xml
.\ethercat-workbench-cli.exe esi-import samples/pdo-choices.esi.xml --device 0 --out .local/choices.json
.\ethercat-workbench-cli.exe esi-import samples/pdo-choices.esi.xml --identity '0x00FF1000/1/1' --out .local/identity-choices.json
.\ethercat-workbench-cli.exe review-pdos .local/choices.json
.\ethercat-workbench-cli.exe select-pdos .local/choices.json --tx-pdo '0x1a01@3' --out .local/alternative.json
```

Repeat `--tx-pdo` or `--rx-pdo` with `INDEX@SM` in desired order. Supplying a direction replaces that direction's choices; omitting it preserves the current/default choices. A sole `none` clears a direction if constraints permit. The same options work with `esi-import`. The bundled default choice profile matches the CoE virtual model. Its alternative has the same input byte count but different mapping and is rejected against that model before SAFEOP. Attached selections compare full SyncManager/PDO order and descriptors, including padding, when readback is available. An unavailable readback stays explicitly unverified. Selecting PDOs sends no bus assignment writes. [PDO selection details](docs/pdo-selection.md) describe limits and unsupported annotations.

Live discovery is read-only on the selected NIC. It retains optional ESC information and error-counter reads, full port link/loop/signal states and decoded common AL codes with raw values. The GUI labels these as discovery snapshots and keeps them separate from current cyclic state. Missing optional reads remain unavailable. Use `scan-virtual` for an in-memory discovery preview or `decode-esc samples/esc-diagnostics.json` for offline register interpretation. [ESC diagnostics](docs/esc-diagnostics.md) describe register scope, write-audit cases, unknown codes and limits; port states do not establish a branch topology or physical input validity. Select a profile with exact identity and Tx/Rx lengths. The initial live implementation requires one isolated SubDevice. The separate approval covers EtherCrab ESC initialization, configuring SyncManagers and FMMUs from the device's existing mapping, requesting SAFEOP and returning to INIT. During that session the cyclic path uses read datagrams only. OP, PDO assignment writes and live RxPDO transmission are outside this preview. After setup, Workbench reads enabled process SyncManagers and the SII mailbox protocol declaration. It reads CoE PDO assignments on CoE devices and SII PDO categories on devices that declare no CoE support. It compares object indexes, subindexes, widths and bit positions with referenced profile fields before requesting SAFEOP. A known mismatch stops setup and requests INIT. Setup confirms SAFEOP with a clear AL error flag and zero AL status code before cycling. Cleanup acknowledges AL errors, requests INIT and confirms a cleared status. A setup failure retains its AL status and code before cleanup. Reports and the GUI retain the readback, identify CoE or SII as the mapping source, and show each field as matched, manual, unavailable or mismatched. Devices with unavailable CoE readback retain an explicit verification warning. Manual fields describe the selected bits and bytes. Verify input changes on the bench before relying on field labels.

```powershell
.\ethercat-workbench-cli.exe nics
.\ethercat-workbench-cli.exe scan --nic '\Device\NPF_{your-nic-guid}'
# Run after approval for the isolated bench and ESC writes.
.\ethercat-workbench-cli.exe run .local/bench.json --backend safeop --approve-esc-writes --seconds 20 --csv .local/bench.csv
```

Typed RxPDO values can be staged offline in **Outputs**, or with `stage-rx samples/output-staging.json --set '2=-1234' --out .local/staged.json`. Preview raw bytes and affected overlapping views before applying them to the profile. Range checks, inverse endian/word transforms, explicit zero initialization, conflict rejection and stale-preview checks preserve the offline image. This adds no bus writes or OP entry. [Typed staging instructions](docs/output-staging.md) cover value syntax, provenance and new-file saving.

Runtime reports and the desktop now separate spacing between all received replies from spacing between valid PDO inputs. The latter includes gaps across bad WKC/AL replies and timeouts, independent of CSV every-valid/on-change selection. Saved comparisons retain per-trial values and complete-group valid-input p99 ranges; missing older metadata stays unavailable. See [valid-input timing](docs/benchmark-comparison.md#valid-input-spacing).

The bundled raw-frame replay fixture contains twelve authored Ethernet exchanges. Replay uses the live LRD/AL reply parser and the normal capture queue and CSV writer. It reports malformed or stale candidates as ignored frames and checks Working Counter and AL state before logging. It stops at the end of the fixture, and a duration limit that cuts a replay short produces an error. Playback spacing and timestamps come from the host clock during the replay. The fixture covers the cyclic input path.

Use `inspect-pcap .local/bench.json .local/bench.pcap --station 0x1000 --out .local/inspection.json` or the desktop's **Review → Ethernet PCAP** controls to inspect saved classic Ethernet PCAP or supported PCAPNG offline. It recognizes Workbench's input-only LRD/AL signature, counts WKC/AL quality and unmatched/truncated packets, and previews raw/typed TxPDO values. For multi-interface PCAPNG, pass `--interface ID` or enter a desktop **PCAPNG interface**. Up to 32 descriptors in one section are supported; only the selected Ethernet interface contributes to counts and timing. The desktop job freezes the current commissioning profile, station, interface choice and preview limit, supports cancellation and exports the same schema as the CLI. Recorded request/reply spacing stays separate from application cycle timing; timestamp regressions suppress spacing summaries. Declared PCAPNG statistics now retain per-interface losses without combining snapshots; missing counters remain unavailable, and reported zeros do not prove complete capture. Inspection uses file I/O without Npcap or packet transmission. [PCAP inspection details](docs/pcap-inspection.md) cover supported formats, bounds, independent frame counts and limits of capture-clock evidence.

The virtual controller backend runs the shared EtherCrab setup and teardown against authored CoE and SII ESC models in memory. It provides SII identity and mailbox descriptors, CoE expedited, normal and segmented uploads, process SyncManagers, FMMUs and SAFEOP input reads. Its SAFEOP response depends on the configured SM/FMMU registers. Reports include SII/CoE counts, state requests and output-write audit counters. Use the corresponding bundled virtual profile and select the model in the GUI or with `--virtual-model coe` or `sii`. The CLI supports `--virtual-fault pdo-order`, `safeop-reject`, `mailbox-abort`, `readback-unavailable`, `cleanup-reject`, `setup-timeout` and `io-timeout` to exercise failure paths. Mailbox and unavailable-CoE faults apply to the CoE model. The `coe` and `sii` models declare no Distributed Clock support. The `coe-dc` model adds authored 64-bit DC capability, receive-time latching and offset/delay registers; use `samples/virtual-dc.json`. Its audit records clock setup writes separately from DC enable and clock-distribution requests. The `dc-active` and `dc-readback-unavailable` faults apply to this model and stop setup before cyclic input. The `io-burst` fault drops forty consecutive cyclic replies and then recovers; `io-lost` drops replies from the ninth read onward. `transport-error` injects a cyclic transport failure with working cleanup, while `transport-lost` keeps the transport unavailable during cleanup. All virtual timestamps measure host execution.

CoE setup readback uses a bounded, read-only Workbench uploader after EtherCrab configures the process image. It reads synchronization types, optional CoE cycle/minimum-cycle values, the optional 0x1008 device name and individual PDO assignment/mapping objects. CoE cycle values are setup snapshots in nanoseconds, separate from requested host microseconds, measured frame spacing and DC cycle registers; absent/aborted values are not replaced with zero. Malformed timing replies stop setup and retain partial diagnostics before INIT cleanup. Reports and the GUI keep the CoE name separate from the SII name. The uploader handles expedited, normal and segmented replies, checks object identity, mailbox counters, segment toggles and declared lengths, and retains initial partial data. Malformed or unsupported transfers stop setup before SAFEOP and confirm INIT cleanup when the transport permits. A valid server abort leaves the corresponding optional value or mapping unavailable. No mailbox work runs inside the cyclic exchange.

Use `samples/virtual-normal.json --virtual-model coe-normal` or `samples/virtual-segmented.json --virtual-model coe-segmented` with the virtual backend. These models change upload policy after process-image configuration; EtherCrab's earlier private initializer still needs expedited replies for its small PDO objects. The new `init-normal-upload` and `init-segmented-upload` virtual faults reproduce that earlier incompatibility and retain the first injected object/reply form in a failure receipt with confirmed INIT cleanup; they add no compatibility fix. Segmented-model faults are `segment-toggle`, `segment-size`, `segment-timeout`, `mailbox-counter`, `segment-abort` and the valid `segment-initial-data` variation. The [source review](docs/ethercrab-review.md#coe-upload-coverage-in-version-090) records transfer bounds, remaining initialization limits and the SOEM comparison.

ESI DC modes can be staged for offline review in the GUI or imported with `--dc-mode` and an optional explicit `--sync-unit-cycle-ns` assumption. The importer retains both `Device/Dc/OpMode` and `Device/OpMode/Dc` forms, assignment/activation, cycle literals, factors, signed shifts and timing annotations. Unknown extensions are flagged. Plain mode-specific SyncManager SyncType and ordered PDO hints are now retained and reviewed separately against available CoE readback and the profile's offline choices; unsupported annotations remain unresolved. The profile retains the ESI filename, hash and exact device identity. Reimporting an ESI clears the staged mode and assumption. Selecting a mode leaves runtime policy at disabled SYNC and sends no configuration writes. The requested host period remains independent. The bundled `samples/sync-review.json` demonstrates staging against the authored CoE/DC model. The CLI's explicit [mode PDO staging](docs/pdo-selection.md#stage-pdo-choices-from-an-esi-mode) command can preview a new offline assignment from supported hints, preserving unchanged decoder settings and staged output bytes. The desktop now exposes the same preview/apply workflow in **Mappings → ESI synchronization**, including explicit Rx-byte clearing and stale-preview checks. It updates the offline profile in memory; use **Profiles… → Save new** to retain it. It does not configure the device.

```powershell
.\ethercat-workbench-cli.exe esi-import samples/sync-modes.esi.xml --device 0 --dc-mode 2 --sync-unit-cycle-ns 1000000 --out .local/dc-review.json
.\ethercat-workbench-cli.exe review-sync .local/dc-review.json
.\ethercat-workbench-cli.exe esi-import samples/mode-sync-managers.esi.xml --device 0 --dc-mode 0 --out .local/mode-sm.json
.\ethercat-workbench-cli.exe review-sync .local/mode-sm.json
.\ethercat-workbench-cli.exe review-sync .local/dc-review.json --readback .local/saved-run.json
```

Review output identifies ESI values and the manual sync-unit assumption. Missing assumptions, nonintegral timing and device-dependent shifts remain unresolved. The optional saved run must identify exactly one device matching the profile. Comparisons cover the full assignment/activation word and SYNC0/SYNC1 cycle registers; absent values remain unavailable. A matched register comparison does not establish that the selected mode was applied or that clocks are aligned. Run reports contain the same staged review, with readback when available. [Timing rules and limits](docs/esi-sync-review.md) describe the supported subset. ESI import is limited to 16 MiB and 64 DC modes, with namespace-aware selectors and numeric checks. These are consumer checks, not full ESI XSD validation.

The JSON `synchronization` section records the readback source, CoE sync types, DC support, requested disabled SYNC mode, initial offset setup attempt, static-sync iteration count and cyclic clock-distribution policy. On DC-capable devices it records the read-back signed time offset and propagation delay. Enhanced DC devices also provide activation and SYNC0/SYNC1 cycle registers. Each attempted register read includes either a value or an unavailable reason; unsupported or not-yet-attempted registers are null, with enhanced-SYNC capability reported separately. The GUI exposes the same detailed readback. Unexpected active SYNC bits or unavailable activation on an enhanced DC device stop setup and request INIT. The current input-only cycle has zero static drift-compensation iterations and sends no cyclic FRMW clock-distribution frames. These settings and readbacks describe startup configuration; they do not establish device clock alignment or synchronization accuracy. Host frame spacing remains a separate measurement.

The CLI prints a JSON report; add `--report .local/new-run.json` to write UTF-8 directly to a new file. An existing report path prevents the run from starting. Save a GUI run report after the session ends. The GUI shows live AL status and expected/actual WKC, raw TxPDO and typed values, requested period, synchronization and separate send/receive spacing. CSV runs on a separate writer thread behind a bounded preallocated queue. Each valid selected exchange is timestamped near receive using a monotonic clock. Rows contain a UTC capture anchor, elapsed microseconds, one-based sample index, connection generation and cycle index. With rotation, parts are named `capture.0001.csv`, `capture.0002.csv`, and so on. Existing files are preserved. Overruns count dropped offers and can cause sample-index gaps. On-change mode compares selected bits with the last queued row and includes the first valid value. A GUI session increments its generation for each run and each capture opens a new file series.

Send and receive spacing are host timestamps taken near Npcap injection and dequeue. The synthetic fixture measures the same application paths against generated data. Missed deadlines count full elapsed slots at the next dispatch. Deadline mode skips elapsed slots and relative mode rebases the next cycle. The run report separates WKC mismatches, AL mismatches, reply timeouts and logger overruns. A normal GUI close or CLI Ctrl+C stops the worker and drains the writer. Setup waits observe the stop signal and release pending PDUs. Cleanup continues through the INIT confirmation. A cancelled run records `cancelled: true`, and cleanup failures retain their error details.

Profiles now include `input_loss_timeout_ms`, defaulting to 1,000 ms for both new and older profiles. A nonzero limit stops a continuous interval of unusable cyclic input, requests the session's approved INIT cleanup and drains CSV. Set it to `0` to monitor until the selected run duration ends. The CLI can override it with `--input-loss-timeout-ms`; the GUI exposes the same setting. Timeouts, wrong WKC and invalid or unavailable AL status all count as unusable input. The interval starts at the first failed exchange's send timestamp and ends at the next valid receive. The policy is checked between exchanges and on normal loop exit; driver blocking and host scheduling can delay enforcement. A fatal transport error stops immediately. A transport or loss failure and a failed cleanup are retained together.

The JSON `input_health` section records the current issue, consecutive and longest invalid streaks, interval count, recoveries, last valid cycle, age and longest invalid interval. Its elapsed timestamp starts at the cyclic loop; CSV keeps its separate capture-start anchor. A recovery means the same read cycle regained valid input before stopping. It uses the same connection generation and performs no automatic reinitialization. Every-valid CSV contains all valid replies before and after an interruption and omits invalid exchanges. On-change CSV continues to compare selected bits with the last queued row, including across gaps. Reply loss, transport failure and logger queue overruns remain separate counters. Cycles include a fatal transport attempt; send/receive spacing excludes that failed call because its timestamps are unavailable. GUI payloads are labeled as the last received data, with a monotonic age for the last valid receive; quality transitions request an immediate nonblocking snapshot update. Typed values are hidden when the latest published exchange is invalid or the run is stopping. Confirmed INIT cleanup updates the reported device state.

Completed reports include a versioned snapshot of the effective profile, application/frontend, fixture options, duration and logging settings, plus a measured cyclic interval. Use `compare-runs .local/deadline.json .local/relative.json` on 2–32 saved trials in capture-start order. It checks that the effective profile differs only by scheduler, and that backend, frontend, duration, observed device/PDO and synchronization settings agree. It retains per-run timing/loss counters and summarizes individual p99 values without pooling percentiles. Old reports without context must be recollected. By default comparison checks saved JSON counters. Add one `--csv BASE` per report to audit its CSV files as well. Neither mode establishes hardware acceptance. The [trial comparison procedure](docs/benchmark-comparison.md) covers repeated GUI-plus-logger bench runs and offline examples.

Use `verify-capture .local/trial.json .local/trial.csv` to audit a saved capture directly. It streams the declared parts, checks exact headers and typed text, validates timestamps/generation/indexes across rotation, and accounts for logger overruns separately from invalid exchanges. It returns raw-byte hashes and retains failed/cancelled run outcomes. The [CSV audit rules](docs/capture-audit.md) describe the writer dialect, bounds, NaN ambiguity and limits of saved-file evidence.

The desktop's **Review** panel runs those audits and comparisons on a separate file worker. Enter report/CSV paths, order trials, inspect per-run timing/loss tables and export the result to a new JSON file. Captured run outcomes and input hashes remain visible. Review jobs are exclusive with bus/discovery starts and support cooperative cancellation; completed results retain their original inputs when editor paths change. [Desktop review instructions](docs/desktop-review.md) describe the controls and evidence limits.

See the [EtherCrab source review](docs/ethercrab-review.md), [verification results](VERIFICATION.md), and [roadmap](ROADMAP.md).

An opt-in [read-only loopback HTTP input feed](docs/http-input-feed.md) now exposes status, latest input, bounded cursor history and setup metadata. Start `run samples/http-input.json --seconds 20` and read `http://127.0.0.1:8766/v1/latest`. It has separate queue/history/client loss counters, explicit freshness and no output/configuration routes. The opt-in [MQTT input publisher](docs/mqtt-input-feed.md) sends latest input/status to a trusted local broker with independent coalescing/error counters. The opt-in [Windows shared-memory input](docs/shared-input-feed.md) provides a fixed C-readable raw/quality snapshot with zero-wait publication, process/age checks and independent contention counters. The portable CLI [reads and inspects these snapshots](docs/shared-input-review.md) with exact-profile typed decoding and explicit historical/stale state. The desktop now [reviews saved snapshot files](docs/desktop-review.md#inspect-a-saved-shared-input-snapshot) using the same decoder, three mapping choices and a cancellable file worker. Optional C-compatible FFI/C# embedding remains [planned](docs/interfaces-roadmap.md).
