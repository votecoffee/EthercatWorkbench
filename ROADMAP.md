# EtherCAT Workbench roadmap

The desktop now uses the EthernetIP Workbench workflow tabs with persistent stop/status controls, focused connection/profile/decoder dialogs and separate saved-review pages. The grouped capture page verifies portable replay bundles and shows saved timing, per-cycle clock and PDO quality, and CSV completion. [Navigation](docs/desktop-workspace.md) and headless workflow checks are implemented; native visual/usability acceptance remains pending.

## Software interfaces, documentation and skills

- The opt-in [read-only HTTP input feed](docs/http-input-feed.md) now has bounded queue/history, explicit invalid/stale state, independent feed loss counters and headless slow-client coverage. Its physical timing impact remains unqualified. The opt-in [MQTT publisher](docs/mqtt-input-feed.md) now has independent queue/coalescing/write counters, bounded local-broker reconnects, explicit invalid/stale state and headless broker-fault coverage. The opt-in [Windows shared-memory input](docs/shared-input-feed.md) now has a fixed C-readable layout, independent bounded worker, explicit age/process checks, zero-wait contention counters and Windows reader/crash coverage; the portable [native reader/inspector](docs/shared-input-review.md) now provides exact-profile typed decoding, coherent raw export and explicit live versus historical evidence; the [desktop saved-snapshot panel](docs/desktop-review.md#inspect-a-saved-shared-input-snapshot) now shares that decoder with frozen mapping choices, cancellation, historical quality labels and new-file export; see the [interface roadmap](docs/interfaces-roadmap.md).
- Evaluate optional C-compatible FFI for C# embedding based on whether the host must own the hardware connection. Define single NIC/session ownership, runtime/thread/allocator/shutdown behavior and bounded callbacks/polling. It has been discussed, not implemented, in the read-only EthernetIPWorkbench reference; no embedding API exists here.
- Maintain [operations](docs/operations.md), [development](docs/development.md), the repository [AGENTS entry point](AGENTS.md) and the [Codex skill](skills/ethercat-workbench/SKILL.md) with each feature. The skill installer binds a discoverable local copy to the source/portable root. Cover ESI/manual setup, CLI, mappings/staging, timing/losses, interfaces, tests, packaging and hardware authorization; keep planned interfaces separate from current commands.

## One-device bench acceptance

The [first bench session guide](docs/bench-qualification.md) includes an offline rehearsal that runs both schedulers and verifies a portable evidence bundle, plus a worksheet for the selected physical device.

The desktop preflight now reviews expected identity/images, requested host cycle and capture settings, and binds its acknowledgement to those effective settings plus scoped discovery. New scans/NIC refresh invalidate it. Only successful physical snapshots on the selected NIC inform the single-device topology check; virtual, failed and other-NIC observations remain separate. Headless controls and preflight are covered; this is not native or physical acceptance.


- The CLI and desktop host check now observe installed Npcap x64 headers/file versions, local service state and recorded AdminOnly policy without probing an adapter. Missing/denied/invalid states have fixture coverage and host/export checks; the focused desktop window now collects/exports through an exclusive background job with headless lifecycle/layout coverage. Actual DLL/export compatibility, effective NIC access and driver/device qualification remain pending.
- Record device model and revision, ESI hash, NIC and driver version, bench wiring, selected input and an independent way to vary or observe it.
- Use read-only discovery to confirm a single SubDevice. Review and approve the ESC setup and INIT teardown scope before starting the GUI SAFEOP run.
- Confirm exact identity, AL state and status code, device-reported image lengths and sync settings. Optional CoE cycle/minimum snapshots now have expedited/normal/segmented and optional-abort/malformed-size coverage, separate from host/DC timing; physical support, dynamic-value meaning and any device measurement procedure still need qualification. Read-only ESC controller/port/counter snapshots and common AL decoding now have authored-fixture coverage; physical counter support and interpretation remain unqualified. Verify PDO offsets and values against the device documentation and an independently observed input change.
- Qualify the new separate valid-input spacing under physical WKC/AL interruptions and unchanged inputs. Runtime/CSV/legacy-comparison and headless layout checks now cover the measurement, but its GUI/logger timing impact remains unqualified.
- Run deadline and relative schedules at 1,000 µs with the GUI and the same CSV settings active. Use repeated runs, retain the JSON reports and use `compare-runs` to check equivalent settings and compare WKC, elapsed timestamps, missed slots, losses and send/receive gap percentiles. The versioned run context and saved comparison workflow now have headless fixture coverage; `verify-capture` and optional CSV audits in `compare-runs` now check saved-file structure, typed text, metadata and declared losses. The desktop saved-run review panel now exposes those tools through one cancellable file worker with immutable job inputs and new-file exports; its controller has headless coverage and the UI is compiled. PDO meaning, native GUI operation and independently observed input changes still require review. If wire timing is needed, compare with an external capture. The `inspect-pcap` tool and desktop PCAP review now check authored classic PCAP and explicitly selected PCAPNG interfaces, input quality and recorded frame spacing. The desktop job freezes the commissioning profile and uses the cancellable saved-file worker; worker/export and pure egui layout checks remain separate from native GUI qualification. Qualify capture placement, clock and losses before using physical timestamps. PCAPNG now supports up to 32 descriptors in one section with an explicit Ethernet-interface selection, per-interface clocks/counts and original file packet indexes. Additional sections and generic EtherCAT dissection remain unsupported; declared Interface Statistics Blocks now retain per-interface counters and timestamps in file order, including missing/zero and repeated/decreasing snapshots. These declarations are not summed and do not independently establish complete capture or clock accuracy. Qualify the physical capture tool and placement on the selected bench.
- If SAFEOP requires vendor configuration or the device only provides valid input in OP, review the needed operations with the user before any writes. Compare SOEM if the issue is a material EtherCrab gap for this device.

## Offline output preparation

- Typed RxPDO staging now has encoder, overlap/range, stale-profile, CLI round-trip and headless GUI layout coverage. Values remain offline in the saved profile; mapping provenance is separate from manually entered values. Native GUI interaction and any device-specific live-output contract remain unqualified.

## Extend bench coverage

- Qualify register-backed virtual TxPDOs with a vendor ESI and device. Offline review covers contiguous byte-aligned register projections, available saved ESC bytes, bytewise or bitwise logical placement across one or more slots in a saved FMMU table, and raw decoding from an addressed logical payload or a checked Workbench LRD reply with optional same-frame AL and topology verification. Schema 4 derives the expected Working Counter from the saved FMMU table and withholds ambiguous logical ranges. Contiguous sub-byte declarations can be reviewed with a manual start bit. An ESI-bound JSON layout supports non-overlapping register fields and explicit zero-filled padding, with per-entry availability. A fully verified schema-4 reply can export one PDO for the standard offline decoder. Automatic physical interpretation of vendor sub-byte layouts, live FMMU allocation and device-specific access remain open. [Register-backed virtual TxPDOs](docs/pdo-selection.md#review-virtual-txpdos-backed-by-esc-registers)
- Qualify offline virtual PDO template geometry with the selected device and its vendor mapping constraints. Workbench supports explicit entries for entryless device templates and comparison with saved CoE readback. Virtual module PDO templates still need separate interpretation. [Virtual PDO templates](docs/pdo-selection.md#preview-an-entryless-virtual-pdo-template)
- Extend bench coverage to physical driver disconnect/reconnect behavior and device-specific recovery. Expedited/normal/segmented setup readback, malformed mailbox replies, cancellation, timeout bursts, sustained reply loss and injected transport errors have offline coverage. The [virtual SYNC0 rehearsal](docs/ethercrab-review.md#virtual-sync0-rehearsal) covers one enabled reference clock, exact-width SYNC0 and SYNC1 programming, explicit and staged ESI timing, separate DC and input WKC failures, and deactivation readback. Add licensed, sanitized fixtures for the selected physical device.
- Qualify the CoE and SII mapping readback on the selected physical device. Check whether that device returns expedited small PDO objects during EtherCrab's private initialization; normal or segmented replies at that earlier stage remain unsupported. The init-normal-upload and init-segmented-upload fixtures now reproduce rejection at the first one-byte 0x1C13:00 mapping count and verify no cyclic/output traffic plus INIT cleanup. Ordinary expedited CoE and SII controls, and post-PDI normal/segmented uploads, still pass; physical reply policy and any fix remain unqualified. Compare a bounded initializer change or SOEM if this is a material device gap. Modular ESI review now retains slot declarations, matching local modules and PDO template summaries. The fixed-slot preview resolves separate PDO and object indexes from explicit choices and compares them with identity-matched PDO readback from a saved run. The offline payload decoder uses saved bit positions for descriptor-matched device and module PDOs in both directions. It exports reusable profiles with position and readback provenance. Saved configured and detected module IDs can check manual choices or supply slots from a complete detected list. The virtual PREOP collector exercises both uploads and saves snapshots with their virtual source, including SDO aborts, malformed counts and an empty list. It also reads PDO assignments, descriptors and SyncManager lengths in the same session. A same-width mapping change withholds the affected decoder fields. The optional fixed-slot fixture keeps an empty middle position through readback and profile export, preserving the later module's index increments. Physical PREOP module readback needs a selected device and reviewed setup. The grouped fixed-slot fixture resolves group-relative mappings, exclusions and entry indexes using device or per-slot increments, then verifies them against virtual PDO readback. Repeated declarations expand in declaration order before inventory and PDO checks. Variable-count declarations now accept explicit instance counts and keep them in saved profiles. Templates can now mix slot and group dependencies across distinct indexes. Saved readback checks device and module PDO group order within each SyncManager and checks assigned padding. Explicit offline assignment requests compose expected PDO images, calculate padding for whole groups and accept explicit padding for groups split across SyncManagers. An identity-bound saved-run inspector retains ESI CoE PDO capabilities, compares uploaded layouts with an offline selection and shows raw values at observed offsets. Observed PDO layouts now export offline profiles with supported ESI scalar types and explicit choices for unknown entries. Extend coverage for virtual PDOs and device-specific synchronization using device examples. Retained PDO catalogs, offline choices and full assignment comparison now have authored-fixture coverage. Headless ESI import now supports unique exact identity selection and optional identity guards on indexes, with multi-product/revision, reorder and duplicate-entry checks; this binds offline selection without establishing bus identity. Structured ESI DC modes, staged timing previews and register comparisons now have offline coverage; plain mode-specific SM SyncType/PDO hints now have structured retention, bounded validation and separate offline-choice/optional-CoE comparisons. Explicit CLI mode-PDO staging now previews/saves a new candidate, preserves unchanged decoders and staged Rx bytes, and requires explicit clearing when Rx layout changes; actual mapping verification remains independent. The desktop now uses the same frozen plan for preview/apply, guards active acquisition/discovery/review, invalidates stale previews and resets dependent editor/run state after apply. Native GUI interaction and acceptance of these controls remain pending. Oversampling, control-byte changes and mode-specific timing/vendor annotations remain unresolved and require implementation and bench qualification.
- Support device-specific approved DC mode configuration, cyclic reference-clock distribution and qualification of clock alignment and frame timing separately. The native input path retains raw DC diagnostics and rejects unexpected active SYNC settings. The [virtual DC rehearsals](docs/input-group.md#rehearse-two-distributed-clocks) check reference distribution WKC, per-station time and each follower's filtered difference. The three-station variant includes a no-PDO follower and isolates faults at either follower before accepting grouped virtual input. The [combined rehearsal](docs/input-group.md#monitor-station-order-after-the-clock-check) also checks order in the PDO frame after the clocks pass, and exercises a latched hold after order recovers. The [modeled reconnect](docs/input-group.md#requalify-the-clocks-after-a-modeled-reconnect) verifies fresh topology, mapping and SYNC0 readback for both generations. The first clock fault after reconnection keeps PDO input blocked until a qualified exchange. Physical propagation compensation, DC alignment, pulse timing and active multi-station acquisition remain open.
- Extend [offline input groups](docs/input-group.md) into approved bus setup and acquisition. The saved inspector checks LRD WKC, AL, range coverage and TxPDO placement. The [virtual TxPDO readback](docs/input-group.md#read-txpdo-descriptors-from-the-virtual-group) reads SII identity, CoE assignments and SII descriptors on the modeled wire. It exports reusable snapshots and exposes equal-size descriptor changes that leave the register checks healthy. [Replay checks one PDO evidence file](docs/input-group.md#replay-with-one-pdo-evidence-file) against the FMMU and SyncManager replies for every saved connection generation. When the file is a virtual readback report, replay first rebuilds its PDO snapshot from the saved setup and CoE/SII exchanges. Schema 7 fixtures can embed each generation's own raw virtual PDO readback. The virtual wire verifies FMMU and SyncManager registers for two- and three-station groups before producing clean or faulted sequences. The three-station fixture checks the AL and topology of a no-PDO station while retaining the two-contributor LRD WKC. The focused preflight verifies station count and order on both sides of the mapping reads. Its fixtures cover a swap with healthy mapping and input WKC, a swap during readback, unexpected device count, duplicate station address, a missing configured station, shifted logical or physical coverage and invalid channel counts. Group replay writes valid inputs, verifies saved CSV rows and exports a portable bundle that can be reaudited after relocation. The DC fixture adds raw clock verification to replay and distinguishes skipped inputs from unanswered requests. New virtual fixtures retain raw topology, FMMU and SyncManager replies for each connection generation. Replay and bundle audit recheck the ordered replies and rebuild the setup mapping. The monitored virtual topology scenario withholds a swapped station's PDO data and holds its generation until a fresh setup passes. Live readback, live topology-change handling and grouped cyclic logging remain open. Cyclic SAFEOP setup still requires one device.
- An [offline output proposal](docs/output-staging.md#review-a-bench-output-plan) freezes the target, staged/safe images, watchdog/OP assumptions and stop observation. The one-shot rehearsal checks safe preload, staged write, safe restore and confirmed INIT on CoE and SII virtual devices, including the CoE normal/segmented and disabled-SYNC models. Its modeled clock exercises OP limits, late INIT observations and watchdog expiry with either clean OP or an AL error. It covers preload WKC failure, OP rejection, a lost write reply and failed INIT confirmation. Physical output work still needs a selected device, a device-specific safe image and watchdog/stop contract, and explicit approval for the proposed OP and write operations. PDO assignment and configuration writes remain separate work.
