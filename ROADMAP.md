# EtherCAT Workbench roadmap

## Software interfaces, documentation and skills

- Plan a read-only local API, MQTT publishing and Windows shared memory as opt-in consumers with bounded buffers, independent loss/freshness reporting and no acquisition-thread waits. These are not implemented. Define EtherCAT WKC/AL/identity/generation/clock semantics and slow-consumer acceptance before implementation; see the [interface roadmap](docs/interfaces-roadmap.md).
- Evaluate optional C-compatible FFI for C# embedding based on whether the host must own the hardware connection. Define single NIC/session ownership, runtime/thread/allocator/shutdown behavior and bounded callbacks/polling. It has been discussed, not implemented, in the read-only EthernetIPWorkbench reference; no embedding API exists here.
- Maintain [operations](docs/operations.md), [development](docs/development.md), the repository [AGENTS entry point](AGENTS.md) and the [Codex skill](skills/ethercat-workbench/SKILL.md) with each feature. The skill installer binds a discoverable local copy to the source/portable root. Cover ESI/manual setup, CLI, mappings/staging, timing/losses, interfaces, tests, packaging and hardware authorization; keep planned interfaces separate from current commands.

## One-device bench acceptance

- Record device model and revision, ESI hash, NIC and driver version, bench wiring, selected input and an independent way to vary or observe it.
- Use read-only discovery to confirm a single SubDevice. Review and approve the ESC setup and INIT teardown scope before starting the GUI SAFEOP run.
- Confirm exact identity, AL state and status code, device-reported image lengths and sync settings. Read-only ESC controller/port/counter snapshots and common AL decoding now have authored-fixture coverage; physical counter support and interpretation remain unqualified. Verify PDO offsets and values against the device documentation and an independently observed input change.
- Run deadline and relative schedules at 1,000 µs with the GUI and the same CSV settings active. Use repeated runs, retain the JSON reports and use `compare-runs` to check equivalent settings and compare WKC, elapsed timestamps, missed slots, losses and send/receive gap percentiles. The versioned run context and saved comparison workflow now have headless fixture coverage; `verify-capture` and optional CSV audits in `compare-runs` now check saved-file structure, typed text, metadata and declared losses. The desktop saved-run review panel now exposes those tools through one cancellable file worker with immutable job inputs and new-file exports; its controller has headless coverage and the UI is compiled. PDO meaning, native GUI operation and independently observed input changes still require review. If wire timing is needed, compare with an external capture. The `inspect-pcap` tool and desktop PCAP review now check authored classic PCAP and single-interface PCAPNG records, input quality and recorded frame spacing. The desktop job freezes the commissioning profile and uses the cancellable saved-file worker; worker/export and pure egui layout checks remain separate from native GUI qualification. Qualify capture placement, clock and losses before using physical timestamps. Additional PCAPNG sections/interfaces and generic EtherCAT dissection remain unsupported; skipped capture metadata does not establish capture loss or clock accuracy.
- If SAFEOP requires vendor configuration or the device only provides valid input in OP, review the needed operations with the user before any writes. Compare SOEM if the issue is a material EtherCrab gap for this device.

## Offline output preparation

- Typed RxPDO staging now has encoder, overlap/range, stale-profile, CLI round-trip and headless GUI layout coverage. Values remain offline in the saved profile; mapping provenance is separate from manually entered values. Native GUI interaction and any device-specific live-output contract remain unqualified.

## Extend bench coverage

- Extend the virtual ESC fixture to enabled DC synchronization, physical driver disconnect/reconnect behavior and device-specific recovery. Expedited/normal/segmented setup readback, malformed mailbox replies, cancellation, timeout bursts, sustained reply loss and injected transport errors now have offline coverage. The current DC model covers disabled SYNC startup and register readback. Add licensed, sanitized fixtures for the selected physical device.
- Qualify the CoE and SII mapping readback on the selected physical device. Check whether that device returns expedited small PDO objects during EtherCrab's private initialization; normal or segmented replies at that earlier stage remain unsupported. Compare a bounded initializer change or SOEM if this is a material device gap. Expand ESI module, slot, dynamic/virtual PDO and device-specific synchronization support from device examples. Retained PDO catalogs, offline choices and full assignment comparison now have authored-fixture coverage. Structured ESI DC modes, staged timing previews and register comparisons now have offline coverage; mode-specific mapping and timing annotations still require implementation and bench qualification.
- Support device-specific approved DC mode configuration, cyclic reference-clock distribution and qualification of clock alignment and frame timing separately. Current diagnostics retain raw DC registers and reject unexpected active SYNC settings.
- Allocate logical input ranges and expected WKC by group for multiple SubDevices. Add identity-bound profiles per position and topology-change handling.
- Design separately approved mapping writes, OP entry and output publishing with an explicit output contract and a bench teardown procedure.
