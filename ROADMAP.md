# EtherCAT Workbench roadmap

The desktop now uses the EthernetIP Workbench workflow tabs with persistent stop/status controls, focused connection/profile/decoder dialogs and separate saved-review pages. [Navigation](docs/desktop-workspace.md) and headless workflow checks are implemented; native visual/usability acceptance remains pending.

## Software interfaces, documentation and skills

- The opt-in [read-only HTTP input feed](docs/http-input-feed.md) now has bounded queue/history, explicit invalid/stale state, independent feed loss counters and headless slow-client coverage. Its physical timing impact remains unqualified. The opt-in [MQTT publisher](docs/mqtt-input-feed.md) now has independent queue/coalescing/write counters, bounded local-broker reconnects, explicit invalid/stale state and headless broker-fault coverage. The opt-in [Windows shared-memory input](docs/shared-input-feed.md) now has a fixed C-readable layout, independent bounded worker, explicit age/process checks, zero-wait contention counters and Windows reader/crash coverage; the portable [native reader/inspector](docs/shared-input-review.md) now provides exact-profile typed decoding, coherent raw export and explicit live versus historical evidence; the [desktop saved-snapshot panel](docs/desktop-review.md#inspect-a-saved-shared-input-snapshot) now shares that decoder with frozen mapping choices, cancellation, historical quality labels and new-file export; see the [interface roadmap](docs/interfaces-roadmap.md).
- Evaluate optional C-compatible FFI for C# embedding based on whether the host must own the hardware connection. Define single NIC/session ownership, runtime/thread/allocator/shutdown behavior and bounded callbacks/polling. It has been discussed, not implemented, in the read-only EthernetIPWorkbench reference; no embedding API exists here.
- Maintain [operations](docs/operations.md), [development](docs/development.md), the repository [AGENTS entry point](AGENTS.md) and the [Codex skill](skills/ethercat-workbench/SKILL.md) with each feature. The skill installer binds a discoverable local copy to the source/portable root. Cover ESI/manual setup, CLI, mappings/staging, timing/losses, interfaces, tests, packaging and hardware authorization; keep planned interfaces separate from current commands.

## One-device bench acceptance

- The CLI host check now observes installed Npcap x64 headers/file versions, local service state and recorded AdminOnly policy without probing an adapter. Missing/denied/invalid states have fixture coverage and host/export checks; actual DLL/export compatibility, effective NIC access and driver/device qualification remain pending.
- Record device model and revision, ESI hash, NIC and driver version, bench wiring, selected input and an independent way to vary or observe it.
- Use read-only discovery to confirm a single SubDevice. Review and approve the ESC setup and INIT teardown scope before starting the GUI SAFEOP run.
- Confirm exact identity, AL state and status code, device-reported image lengths and sync settings. Optional CoE cycle/minimum snapshots now have expedited/normal/segmented and optional-abort/malformed-size coverage, separate from host/DC timing; physical support, dynamic-value meaning and any device measurement procedure still need qualification. Read-only ESC controller/port/counter snapshots and common AL decoding now have authored-fixture coverage; physical counter support and interpretation remain unqualified. Verify PDO offsets and values against the device documentation and an independently observed input change.
- Qualify the new separate valid-input spacing under physical WKC/AL interruptions and unchanged inputs. Runtime/CSV/legacy-comparison and headless layout checks now cover the measurement, but its GUI/logger timing impact remains unqualified.
- Run deadline and relative schedules at 1,000 µs with the GUI and the same CSV settings active. Use repeated runs, retain the JSON reports and use `compare-runs` to check equivalent settings and compare WKC, elapsed timestamps, missed slots, losses and send/receive gap percentiles. The versioned run context and saved comparison workflow now have headless fixture coverage; `verify-capture` and optional CSV audits in `compare-runs` now check saved-file structure, typed text, metadata and declared losses. The desktop saved-run review panel now exposes those tools through one cancellable file worker with immutable job inputs and new-file exports; its controller has headless coverage and the UI is compiled. PDO meaning, native GUI operation and independently observed input changes still require review. If wire timing is needed, compare with an external capture. The `inspect-pcap` tool and desktop PCAP review now check authored classic PCAP and explicitly selected PCAPNG interfaces, input quality and recorded frame spacing. The desktop job freezes the commissioning profile and uses the cancellable saved-file worker; worker/export and pure egui layout checks remain separate from native GUI qualification. Qualify capture placement, clock and losses before using physical timestamps. PCAPNG now supports up to 32 descriptors in one section with an explicit Ethernet-interface selection, per-interface clocks/counts and original file packet indexes. Additional sections and generic EtherCAT dissection remain unsupported; declared Interface Statistics Blocks now retain per-interface counters and timestamps in file order, including missing/zero and repeated/decreasing snapshots. These declarations are not summed and do not independently establish complete capture or clock accuracy. Qualify the physical capture tool and placement on the selected bench.
- If SAFEOP requires vendor configuration or the device only provides valid input in OP, review the needed operations with the user before any writes. Compare SOEM if the issue is a material EtherCrab gap for this device.

## Offline output preparation

- Typed RxPDO staging now has encoder, overlap/range, stale-profile, CLI round-trip and headless GUI layout coverage. Values remain offline in the saved profile; mapping provenance is separate from manually entered values. Native GUI interaction and any device-specific live-output contract remain unqualified.

## Extend bench coverage

- Extend the virtual ESC fixture to enabled DC synchronization, physical driver disconnect/reconnect behavior and device-specific recovery. Expedited/normal/segmented setup readback, malformed mailbox replies, cancellation, timeout bursts, sustained reply loss and injected transport errors now have offline coverage. The current DC model covers disabled SYNC startup and register readback. Add licensed, sanitized fixtures for the selected physical device.
- Qualify the CoE and SII mapping readback on the selected physical device. Check whether that device returns expedited small PDO objects during EtherCrab's private initialization; normal or segmented replies at that earlier stage remain unsupported. The init-normal-upload and init-segmented-upload fixtures now reproduce rejection at the first one-byte 0x1C13:00 mapping count and verify no cyclic/output traffic plus INIT cleanup. Ordinary expedited CoE and SII controls, and post-PDI normal/segmented uploads, still pass; physical reply policy and any fix remain unqualified. Compare a bounded initializer change or SOEM if this is a material device gap. Expand ESI module, slot, dynamic/virtual PDO and device-specific synchronization support from device examples. Retained PDO catalogs, offline choices and full assignment comparison now have authored-fixture coverage. Headless ESI import now supports unique exact identity selection and optional identity guards on indexes, with multi-product/revision, reorder and duplicate-entry checks; this binds offline selection without establishing bus identity. Structured ESI DC modes, staged timing previews and register comparisons now have offline coverage; plain mode-specific SM SyncType/PDO hints now have structured retention, bounded validation and separate offline-choice/optional-CoE comparisons. Explicit CLI mode-PDO staging now previews/saves a new candidate, preserves unchanged decoders and staged Rx bytes, and requires explicit clearing when Rx layout changes; actual mapping verification remains independent. The desktop now uses the same frozen plan for preview/apply, guards active acquisition/discovery/review, invalidates stale previews and resets dependent editor/run state after apply. Native GUI interaction and acceptance of these controls remain pending. Oversampling, control-byte changes and mode-specific timing/vendor annotations remain unresolved and require implementation and bench qualification.
- Support device-specific approved DC mode configuration, cyclic reference-clock distribution and qualification of clock alignment and frame timing separately. Current diagnostics retain raw DC registers and reject unexpected active SYNC settings.
- Allocate logical input ranges and expected WKC by group for multiple SubDevices. Add identity-bound profiles per position and topology-change handling.
- Design separately approved mapping writes, OP entry and output publishing with an explicit output contract and a bench teardown procedure.
