# ESI synchronization review

Workbench imports an offline subset of `Device/Dc/OpMode` and `Device/OpMode/Dc`. Each mode retains its name, description, XML path, `AssignActivate`, cycle and shift values, factors, input flags and input/output delay annotations. Unknown children and attributes are flagged. Selecting a mode stages a review and preserves the ESI filename, SHA-256 and exact device identity. Runtime policy still requests disabled SYNC. The preview never configures device clocks, changes PDO assignments, enters OP or publishes staged outputs.

The resolver follows the timing rules documented in the [ESI schema published with Synapticon's SII tool](https://github.com/synapticon/siitool/blob/c46570adb1228eada44ae1f38bd61a81fab99c98/examples/ModulesSlots_DS402_Simple/EtherCATInfo.xsd). A nonzero cycle literal takes precedence over its factor. For a zero SYNC0 literal, a positive factor multiplies the explicit sync-unit assumption and a negative factor divides it. For a zero SYNC1 literal, a positive factor multiplies the resolved SYNC0 cycle; a negative factor multiplies the sync-unit assumption by the factor's absolute value. The negative-factor rules differ between SYNC0 and SYNC1.

The sync-unit assumption is a separate manual profile setting. Workbench does not substitute the requested host period. Missing dependencies, nonintegral division, negative cycles and results outside a 32-bit cycle register remain unresolved. Signed shift literals are retained; factors, input flags and delay annotations that need device timing remain unresolved. Shift values are not compared with the absolute ESC start-time register. The plain mode-specific SyncManager subset below is structured; other extensions and vendor parameters remain review notes.

The run report keeps the selected mode and assumption in `sync_review`. Its `applied` field is always false. On enhanced-DC devices, startup reads the little-endian word at `0x0980`/`0x0981` alongside activation and the SYNC0/SYNC1 cycle registers. The review compares these three register values with staged expectations and reports matched, different, unavailable, unresolved or not declared. A match describes only those saved/read-back values; it does not establish a complete operating-mode match, clock alignment or device acceptance.

`review-sync --readback` reads a saved JSON run report and requires its single-device identity to match the profile. Saved data is labeled as a saved report, not a current bus observation. Reports without the newer full assignment/activation readback retain an unavailable result rather than an inferred zero. Differences are review results and do not cause this offline command to fail. Invalid input or an identity mismatch does fail.

## Mode-specific SyncManager hints

Version 0.25 retains `Sm No` and plain `SyncType` on both operating-mode forms. Ordered `Pdo` hints on `Device/Dc/OpMode/Sm` are also retained. The [same source schema](https://github.com/synapticon/siitool/blob/c46570adb1228eada44ae1f38bd61a81fab99c98/examples/ModulesSlots_DS402_Simple/EtherCATInfo.xsd) gives those forms different children: PDO hints on `Device/OpMode/Sm`, oversampling (`OSFac`), control-byte changes, cycle/shift/delay annotations and unknown attributes/children are retained as unsupported notes. They are not applied or silently treated as equivalent simple assignments.

Each nonempty `mode.sync_managers` list records index, optional literal SyncType, ordered PDO indexes and notes. `review-sync`, run `sync_review` and the GUI's staged timing details add a separate `sync_managers` review list with `source: "esi"`. A literal SyncType is compared with an available read of the exact CoE object: SM2 uses `0x1C32:01`, SM3 uses `0x1C33:01`. Other SM indexes have no corresponding readback in this implementation and remain unavailable, even when another direction reports zero. Missing declarations are not declared; unsupported annotations leave the comparison unresolved. A saved report remains historical and identity-bound as described above.

PDO comparisons use the profile's attached ESI selection, grouped by exact SM and preserving chosen order. They compare offline configuration, not discovered bus mapping. A matching list is marked matched with that limit; a different list is different. An absent hint list does not imply an empty assignment. A detached selection is unavailable, and unsupported annotations remain unresolved. Missing catalog entries, vendor semantics, mapping downloads and device acceptance are not inferred from a matching hint. Selecting a mode never changes chosen PDOs, decoder fields, image lengths, staged outputs, host timing or runtime disabled-SYNC policy.

Use the authored fixture to inspect a matching offline choice, a different SyncType expectation and unresolved annotations:

```powershell
.\ethercat-workbench-cli.exe esi-import samples/mode-sync-managers.esi.xml --device 0 --dc-mode 0 --out .local/mode-sm.json
.\ethercat-workbench-cli.exe review-sync .local/mode-sm.json
.\ethercat-workbench-cli.exe review-sync .local/mode-sm.json --readback .local/saved-run.json
```

The consumer allows at most 16 unique SM indexes (0–15) per mode and 512 unique nonzero 16-bit PDO hints per SM. SyncType literals must fit an unsigned 16-bit value; duplicate scalar declarations, duplicate SMs/PDOs and excessive lists fail import or profile validation. Old saved modes without hints load with an empty list, omitted when saved again, preserving their canonical profile content/hash. Profiles with nonempty structured hints require version 0.25 or later. Existing baselines are not reimported automatically. Original ESI basename/hash/device identity remain provenance declarations, not signed authentication of edited profile JSON.

The authored samples demonstrate both XML forms, disabled SYNC, positive/negative factors, negative shifts, plain SM hints and unsupported vendor annotations. XML well-formedness and Workbench consumer checks are tested. Full XSD validation, vendor-specific interpretation, enabled synchronization and physical timing remain outside this preview. Vendor ESI files and raw bench reports belong in ignored `.local/`.
