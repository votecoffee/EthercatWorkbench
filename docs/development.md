# Developing EtherCAT Workbench

Read [AGENTS.md](../AGENTS.md) first. [Operations](operations.md) describes supported user workflows; this guide identifies ownership and change routes. [VERIFICATION.md](../VERIFICATION.md) separates actual offline/native/physical evidence. Keep those boundaries explicit when adding features.

## Desktop shell

`gui_connection.rs` owns discovery origin/job types, proposed SAFEOP settings, pure preflight and settings-bound acknowledgement. The stamp covers the effective profile, duration, normalized CSV path and discovery scope/data; runtime observations are not saved into profiles. Discovery workers carry a frozen physical NIC or virtual-model scope, and invalidate acknowledgement at start/completion. Only a successful snapshot from the current physical NIC participates in topology preflight. The pinned footer stays outside the scrolling review details. `gui_workspace.rs` owns workflow tabs, persistent state/stop/cancel controls, profile/decoder windows and the connection-review modal. `gui_runtime_check.rs` owns the explicit host-prerequisites window, one background metadata/export job, immutable report/export inputs and observation rendering. `main.rs` owns shared editors, session/close lifecycle and detailed diagnostic rendering. App close defers while host work or acquisition drains; closing only the prerequisites window preserves its job/result. Host work participates in the same acquisition/discovery/review exclusion and never invokes the capture backend. `gui_review.rs` keeps reports/CSV, PCAP and saved snapshots on separate pages around one existing worker. Refer to [desktop workflows](desktop-workspace.md); use the read-only EthernetIPWorkbench shell as the layout reference while preserving EtherCAT state/write semantics. Pure egui tests cover page isolation at 820×560 and 1100×840, synthetic navigation, review text, discovery exclusion, invalid retained data and an actual synthetic capture drained after cross-tab stop. Native visual review remains separate.

`gui_profiles.rs` tracks the working profile against the last loaded, saved, or demo baseline. It owns separate load/save paths and the confirmation for replacement or close. Profile saves use the existing create-new writer. Failed replacement keeps the current draft. On close, the app waits for acquisition or host work before handling unsaved changes.

## Data and ownership

`esi/register_pdos.rs` reviews original virtual SyncManager declarations and register geometry. The CLI reuses the bounded ESC snapshot parser in `esc.rs` and hashes the same bytes it decodes. Each entry uses one saved register block. Review output carries the ESI identity and records the absence of identity binding in the snapshot.

`esi/register_pdos/fmmu.rs` compares declared physical register ranges with the selected station in a saved FMMU table. `register_pdos.rs` preserves whole-byte ESI defaults and accepts an opt-in physical start bit by PDO index for contiguous sub-byte layouts. The register layout file binds the selected ESI identity and exact hash and supplies one bit offset per entry. `register_pdos.rs` checks physical bounds and overlap, then passes each separate range to the existing FMMU comparison. It reports the independent results and joins verified segments in ESI declaration order. Explicit zero-index padding contributes a zero-filled span to the packed output with no physical or logical address. Extraction still requires valid saved reply evidence and every mapped span. The register decoder export consumes a verified schema-4 review in memory, then stores the selected packed image, recognized ESI fields and source digests in an offline-scoped standard profile. Multiple PDOs start at separate byte boundaries in the requested order. Saved profile validation checks each PDO's packed range, field membership, manual provenance and unused bits. Source verification rebuilds the decoder from the supplied evidence, checks recorded digests and compares the resulting metadata, packed bytes and typed mappings. Register decoder bundles archive the checked original bytes under fixed names and write the completion receipt after copying. Reopening rebuilds the profile comparison and verifies the recorded file lengths and digests. It shares the FMMU decoder and slot count checks with `input_group/fmmu.rs`. The review clips each covering FMMU to the projected register range and requires exact physical bit coverage. It checks conflicting reads and the documented three-byte spacing between same-station read slots when either slot uses bitwise mapping. The report lists byte-aligned placements as before and uses `matched_bits` for segments with bit offsets or lengths. Saved raw ESC samples are independent of logical placement.

`esi/register_pdos/payload.rs` reads one bounded logical payload file and resolves raw entries through verified FMMU segments. A clipped segment contributes only the bits within the requested entry. Extraction packs bits least-significant first in physical register order and leaves unused upper bits of the final byte zero. Historical snapshot samples use the same bit packing. Any missing bit makes that result unavailable. The saved LRD input uses the existing `wire.rs` frame matcher and retains the expected and actual Working Counter. Schema 2 uses the same AL datagram decoder as grouped SAFEOP review. Schema 3 reuses the group's topology probe and checks the station order from the FMMU table. Schema 4 decodes all saved station banks through the same FMMU checks. It derives one LRD contribution per station with at least one active read range overlapping the logical window. The report carries the clipped bit ranges and keeps an optional declared expectation separate. Invalid station evidence, a derived count of zero, a counter mismatch, unconfirmed SAFEOP, topology mismatch or conflicting configured alias withholds logical samples before extraction. Field extraction also checks other stations' active read ranges for overlapping bits. Source hashes and independent ESC snapshot samples remain in the review.

`preview-pdo-layout` uses the expected-layout composer shared with the modular review. That composer keeps the ESI declaration and manual entries provenance on each chosen virtual template. The directional source marks the resulting expectation. Saved evidence readers reject expected layouts as readback and the comparison requires an explicit CoE source for a direction with manual template entries.

`comparison_files.rs` prepares the recorded report and CSV-part references, validates the audit association, and checks source bytes with bounded memory and cooperative cancellation. Desktop Review passes the opened result hash to the worker. The CLI prints the same per-file status report and offers a create-new receipt.

`comparison_bundle.rs` reuses the source check, verifies hashes while copying files, and writes the portable comparison and a relative trial set. It writes the completion receipt after all other files. The desktop runs it on the review worker with the opened comparison's hash. The worker retains the opened comparison during export and publishes a completed receipt even if cancellation arrives after the export commits. Closing the app requests cancellation and waits for the export worker.

`verify-bundle` and the desktop open action share the same read-only verifier. It checks the completion receipt, metadata hashes, trial rows and fixed source paths before checking file bytes. The desktop uses the checked result directly on the same Review page.

`compare-runs --bundle` and **Recompare bundled trials** reuse the checked bundle metadata and the ordinary scheduler comparison. They check the hashes computed by the fresh comparison against the archived evidence before publishing a result. The desktop request is tied to the receipt hash of the opened bundle.

`compare-runs --out` uses the CLI's create-new JSON export. Desktop **Saved comparison** reads and hashes the selected result on the existing cancellable review worker. `benchmark.rs` checks the saved structure and passes recorded values to the comparison display. Source evidence remains independently reviewable through a fresh comparison.

`trial_set.rs` owns the shared trial-list JSON, bounded reads, relative-reference resolution and create-new saves. It prepares comparison tasks for desktop Review and `compare-runs --trial-set`. `gui_review.rs` confirms draft replacement and installs a fully parsed list and audit option together. The review task checks row completeness before opening evidence and freezes the paths it receives.

`gui_capture_review.rs` retains the final worker report and the CSV base frozen at session start. It suggests a create-new report destination and sends the saved report path and original CSV base to the existing cancellable Review worker. The live display snapshot can be cleared independently of the completed run. The shortcut leaves the editable trial rows available for manual audits and comparisons.

## Verification and release

On Windows x64 with the configured Rust/MSVC/Npcap SDK toolchain:

```powershell
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
cargo build --locked --release --target x86_64-pc-windows-msvc
python -B tools/verify.py target/x86_64-pc-windows-msvc/release .local/new-verification
```

Use a new verification directory. The script authors fixtures under `.local/`, checks CLI/profile/ESI/typed staging, virtual setup/faults, replay, capture containers, CSV audits, repeated scheduler comparisons and HTTP/MQTT/shared memory with stalled consumers, broker faults, named-object/liveness failures, native/saved shared-input review, typed profile guards and invalid input. Rust tests cover desktop snapshot worker/export/layout behavior and frozen PCAPNG interface selection. Mode-PDO desktop tests exercise frozen preview/apply, unchanged output preservation, fresh explicit Rx clearing, profile invalidation, active-work exclusion, unsupported hints and pure egui before/after/provenance layout; shared plan hashing/validation stays in the library. Independent Python-authored multi-interface captures check per-interface clocks/counts, excluded regressions, original packet indexes, empty selections and malformed excluded records. Early initializer fixtures inject normal/segmented PDO responses before process-image configuration, retain the first object/form, require failure plus INIT and verify expedited/SII controls. CoE timing fixtures check optional aborts versus malformed failures, primitive sizes, zero/unavailable/unqueried values, retained failed-setup diagnostics, unchanged upload counts during longer acquisition and legacy metadata. Host-check tests cover x64/x86/ARM64/non-DLL headers, malformed bounds, literal version resources, unreadable versus invalid images, missing/denied policy and unprobed status summaries. CLI checks preserve export paths, cross-check observed PE bytes and require absent Npcap executable modules before/after collection. Timing tests distinguish invalid-reply versus valid-input intervals without CSV, optional legacy metadata, complete-group ranges and unavailable versus zero intervals in a headless snapshot. CLI checks cross-check longest valid gaps against every-valid CSV timestamps and validate on-change independence. Exact-identity fixtures check numeric bounds, multiple products/revisions, reorder stability, guarded-index failure, duplicate ambiguity/disambiguation, legacy imports and non-mutating failures. Mode-PDO staging fixtures check unchanged/changed layouts, decoder and output preservation, explicit Rx clearing, stale plans, rejected hints/catalog constraints, create-new saves and actual virtual mapping rejection before SAFEOP. Mode-hint fixtures check both XML forms, source/hash compatibility, missing/zero/different readback, offline PDO order, detached selections, unsupported extensions and bounds. Statistics fixtures check both byte orders, split-word clocks versus scalar counters, wide integers, missing/zero/decreasing snapshots, malformed references/options and bounded inventories. `tools/mqtt_fixture.py` is an independent bounded TCP fixture, not a production broker. Its optional `--gui` launches native UI and requires explicit authorization; default headless use does not. Pure egui layout tests need no window, desktop input, screenshot or GPU. Test-only binaries may report MSVC LNK4199 for unused delay-loaded Npcap; distinguish that from compiler/Clippy failures.

The Windows shared-memory fixture polls for two increasing HTTP cycle counts while holding the reader mutex. It checks the pinned publication's age against the freshness threshold, checks busy reads and exports, and records the observations in `shared-verification.json`. The virtual loss case accepts a live snapshot with current valid data or retained last-valid history when attaching. It requires an active invalid snapshot and matches the last-valid cycle to the run report and audited CSV. The cyclic, shared-memory and CSV elapsed times are evaluated against their own origins.

Validate a changed skill with the available skill-creator `quick_validate.py` and read it against realistic app requests. `tools/install-skill.ps1` can be exercised against a fresh `.local/` destination before installing it in the user skill directory. Do not overwrite modified/unowned installed files.

From a clean committed checkout, use `tools/package.ps1 -Zip` with a fresh absolute ZIP path. It builds locked release binaries, generates third-party/font/Rust notices, records source commit/toolchain and hashes, and packages docs/samples/skill assets. It does not redistribute the Npcap runtime. Verify every manifest hash, PE x64 GUI/console subsystem and the extracted CLI using its bundled samples; retain receipts under `.local/`. Preserve older deliverables. Push verified cohesive commits when authorized; no automatic Actions tests are configured.

For documentation/skill-only changes, check links, command help/examples, installer preservation and packaging content. Do not rerun unchanged physical/native acceptance or claim new runtime evidence. Application version changes affect saved run context and comparison compatibility, even when behavior is unchanged.

## Protocol and authorization boundaries

EtherCrab is source-pinned; read [the review](ethercrab-review.md) before changing native initialization, Windows transport, mailbox upload or scheduling. The virtual normal/segmented fixtures do not fix the earlier private initializer's expedited-only small-object reads. Compare SOEM for a material selected-device gap; its licensing and backend tradeoffs need source-bound review. Keep optional/unavailable discovery distinct from observed values, including controller counters and synchronization registers.

A 1 ms request is a measurement target. Preserve separate host send/receive gaps, device/DC configuration and capture-clock evidence. Do not pool per-trial percentiles or silently merge generation/index domains. Logger losses, invalid bus exchanges, interface dispatch drops and per-consumer failures must remain independent.

The approved native path configures ESC state/SM/FMMUs and obtains SAFEOP inputs using read-only cyclic datagrams. OP, PDO downloads, live outputs and enabled DC need separate design, tests and explicit user approval before hardware use. Do not infer hardware permission from a profile, staged bytes, a command flag, successful virtual tests or an installed skill. Do not auto-retry ambiguous writes.

## Maintenance

Update the operational guide and relevant detailed docs when behavior/commands change; update this ownership map for new modules. Keep README runnable examples, ROADMAP statuses, AGENTS links, the repository skill and package manifest in sync. Record verification scope and pending physical work without treating stale test counts as current results. Vendor files/raw captures/private profiles stay in ignored `.local/`; reusable fixtures must be authored or licensed/sanitized.

EthernetIPWorkbench is a read-only reference for UX and consumer isolation, not a source of EtherCAT protocol semantics. The read-only loopback HTTP input feed is implemented; [its contract](http-input-feed.md) defines current semantics and bounds. The [MQTT publisher](mqtt-input-feed.md) implements a bounded publish-only subset for a trusted local broker; [Shared memory](shared-input-feed.md) implements a fixed C-readable byte snapshot with zero-wait publication; function FFI remains planned. Avoid advertising planned endpoints or ownership guarantees as implemented behavior.
