# EtherCrab Windows x64 source review

The implementation pins EtherCrab 0.7.1 source at `fec2730823ce1eb62425f83d5df49d678f03b104`. The Windows std backend owns a blocking Npcap capture, requests immediate and nonblocking receive, queues raw Ethernet TX, and passes EtherType 0x88A4 replies to EtherCrab PDU storage. The Windows example uses an Npcap interface identifier such as `\Device\NPF_{GUID}` and recommends the x64 Npcap SDK import libraries for compilation. Ethernet capture and injection use the installed Npcap NDIS filter. An admin-only installation restricts driver access and may require elevation. The Workbench uses Npcap directly for its dedicated cycle thread. It delay-loads the installed DLL from the system Npcap directory, so offline commands and GUI startup can run without the driver. [EtherCrab Windows backend](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/src/std/windows.rs), [Windows setup](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/doc/ek1100-windows.md), [Npcap user guide](https://npcap.com/guide/npcap-users-guide.html)

EtherCrab's manifest and README offer MIT or Apache-2.0. The pinned source checkout lacks the root license files linked in the README. The portable build selects Apache-2.0 for EtherCrab, includes that license in the dependency notices, and records the exact upstream source. Npcap's free edition has a limited deployment allowance and does not grant redistribution. OEM redistribution is a separate license. The package ships the Workbench binaries and notices. Install Npcap from its publisher under the applicable terms. [EtherCrab licensing declaration](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/README.md#license), [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0), [Npcap downloads and license terms](https://npcap.com/#download), [Npcap OEM redistribution](https://npcap.com/oem/redist)

EtherCrab's initialization performs broadcast reset and writes station, EEPROM access, SyncManager, FMMU and DC registers. It reads SII identity and builds the process image from live SII/CoE configuration. `into_pre_op_pdi` configures input FMMUs first from logical address zero for the first group. The Workbench requires a separate approval for these setup writes and SAFEOP/INIT state transitions. It checks the bus count before starting EtherCrab, checks exact identity before configuring FMMUs, and compares actual Tx/Rx lengths with the profile. Read-only discovery uses broadcast and auto-increment register reads to show count, bus order, links, alias and AL status. SII identity appears after approved setup because its read protocol writes ESC request registers. [MainDevice initialization](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/src/maindevice.rs), [Group PDI configuration](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/src/subdevice_group/mod.rs)

The stock cyclic `tx_rx` sends LRW (Logical Read Write) with the group image and returns its aggregated Working Counter and state. The pinned public command API lacks LRD. The Workbench emits one read-only LRD for the input range plus an FPRD for AL state and status code in the same frame. It expects LRD WKC 1 and AL WKC 1 for the single device. A valid exchange also requires SAFEOP and no AL error. This covers an input-only bench run with RxPDOs present while keeping staged bytes on disk and in memory. SAFEOP is expected to update inputs on devices that support this mode. Physical bench acceptance is device-specific. [EtherCrab commands](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/src/command/mod.rs), [Beckhoff EtherCAT commands](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1257993099.html), [Beckhoff EtherCAT state machine](https://infosys.beckhoff.com/content/1033/el2535/1036980875.html)

The stock Windows example uses a relative cycle wait with spin sleep after subtracting elapsed work. The Workbench compares the same relative policy with a monotonic absolute deadline schedule that skips expired slots. Both use the same cycle and logging code and the same spin sleeper. The request, observed host-side send/receive gaps, and configured/reported device synchronization are separate values. Native Windows scheduling and the NIC/driver can introduce jitter. The 1 ms period is a bench measurement target. [EtherCrab Windows example](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/examples/ek1100-windows.rs), [EtherCrab Windows tuning notes](https://github.com/ethercrab-rs/ethercrab/blob/fec2730823ce1eb62425f83d5df49d678f03b104/doc/windows-tuning.md)

The single-device LRW gap is handled by the LRD path. Compare SOEM on the same bench if the selected device cannot enter SAFEOP or return valid input through this path. In that comparison, isolate PDO assignment, SM/FMMU layout, DC mode, driver and scheduler variables. No bench model was selected during the initial build.
