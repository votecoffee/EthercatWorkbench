# EtherCAT Workbench

Use this standalone MainDevice app for EtherCAT bench work. Do not route EtherNet/IP, IO-Link or PLC programming requests here.

## Locate and inspect

Resolve the application root from `ETHERCAT_WORKBENCH_HOME` when set, otherwise from `.application-root` beside this installed skill. For a source checkout use the current repository when it contains `Cargo.toml` for `ethercat-workbench`; on the original workstation the checkout is `C:\~LocalWork\Repos\Programming\~Github\EthercatWorkbench`. If unavailable, locate the user's supplied portable/source folder before issuing commands.

The CLI is `ethercat-workbench-cli.exe` at a portable root, or `target/x86_64-pc-windows-msvc/release/ethercat-workbench-cli.exe` in a built checkout. Check `--version`/`--help`. Read `AGENTS.md` and `docs/operations.md` at the resolved root for the task. For source changes also read `docs/development.md`; detailed operation guides are linked from the operational guide. These files ship in the portable bundle and repository.

## Choose the workflow

- ESI setup: `esi-list`, then `esi-import --identity VENDOR/PRODUCT/REVISION` for a unique exact imported identity, or `--device INDEX` for an explicit list entry. Supply both to guard the index against a mismatched identity. Decimal/0x/#x unsigned 32-bit components are accepted; zero is literal and duplicate identities require an explicit index. Save to a new profile, then `validate`/`review-pdos` and optional `review-sync`. Mode-specific SM SyncType/PDO comparisons describe expectations: PDO checks use offline choices, exact SM2/SM3 CoE readback is optional, other channels remain unavailable, and vendor/oversampling annotations stay unresolved. Mode selection never changes assignments or sends writes. Separately, `stage-mode-pdos PROFILE` previews plain PDO hints; `--out NEW.json` saves a reviewed offline candidate. It preserves unchanged decoder directions and staged Rx bytes, rebuilds changed directions, and requires `--clear-staged-rx` to discard nonempty bytes after an Rx layout change. Unsupported mode/SM hints reject staging. Load the candidate in the GUI or use **Mappings → ESI synchronization → Stage PDO choices from the selected ESI mode** for the same frozen preview and offline apply. Review before/after mappings, fields and bytes; acknowledge staged Rx clearing for each new Rx-change preview. Profile edits and acquisition/discovery/saved-file review invalidate pending previews. Apply changes memory only: use **Profiles… → Save new** afterward. Retain actual-mapping verification; matching offline hints do not establish device compatibility. Manual setup uses explicit identity, image lengths and bit/type/transform mappings. Preserve ESI hashes and distinguish expected/manual/overridden settings from discovered bus evidence.
- Modular ESI: inspect `source.modular` with `esi-list` and `esi.modular` with `validate`. In **Device → ESI modules and slots**, review declared slot limits, identity/class choices and counts of matching local definitions. Templates preserve declared PDO sizes and slot/group index flags for review. The profile imports device-level fields and lengths. Installed modules and composed layouts require separate verification. Try `samples/modular-device.esi.xml` and see `docs/pdo-selection.md`.
- Fixed-slot PDO preview: use `preview-modular-pdos ESI --identity VENDOR/PRODUCT/REV --slot 0=IDENT --slot 1=IDENT [--out NEW.json]` with one explicit identity per declaration. Use guarded `--device` if needed. The preview supports one required instance in each ungrouped slot and shows declared and resolved indexes, per-slot increments, SyncManager hints and device-level index matches. Add `--expect-layout FILE` to compose an expected offline image from explicit device and module assignments. The bundled request is `samples/module-pdo-expected.json` for `samples/module-pdo-group-alignment.esi.xml` with slots `0=0x400` and `1=0x402`. Grouped alignment requires one SyncManager per direction. Add `--run-report` to compare the full planned assignment and descriptors with saved readback. See `docs/pdo-selection.md`.
- Modular readback comparison: add `--run-report REPORT` to the fixed-slot PDO preview. A single exact identity is required. Read each candidate's `saved_readback.state`, differences, bit position, SyncManager hint result and assigned exclusions. The top-level `saved_readback` includes the report hash, source, device PDO comparisons and other assignments. An unavailable direction and an unassigned candidate are separate outcomes. Treat matched descriptors as saved mapping evidence. Use `samples/fixed-slot-pdo-readback.json` for the authored example.
- Modular payloads: use `--tx-hex HEX`, `--rx-hex HEX`, or both with `preview-modular-pdos` and `--run-report`. Supply each complete image at its saved length. The decoder uses saved bit positions for matching device and module descriptors. Unavailable module fields and withheld device assignments are listed under `withheld_pdos` and `withheld_device_pdos` respectively. The report retains the supplied bytes and ESI datatype hints. This is an offline decode. See `docs/pdo-selection.md`.
- Modular profile export: use `export-modular-profile ESI --device INDEX --slot 0=IDENT --slot 1=IDENT --run-report REPORT --out NEW.json` with one explicit choice per slot. Both saved directional lengths are required. Exported field names identify their device or slot origin. Use the standard `validate`, `decode`, `stage-rx` and desktop **Profiles… → Offline decoder…** workflows. **Device → Saved modular layout** identifies the saved provenance. These profiles are scoped to offline use. See `docs/pdo-selection.md`.
- Virtual module inventory: run `read-virtual-module-inventory --out FILE` to upload the fixed-slot fixture's lists in virtual PREOP and save a snapshot for offline review. Add `--pdo-report NEW.json` to collect PDO layout evidence in the same PREOP session. Use the inventory as `--module-inventory` and the PDO report as `--run-report`. Inspect the CLI's wire audit and final INIT observation. The saved snapshot keeps its `virtual_coe` source in previews and exports. See the guide for the fault scenarios.
- Saved module inventory: use `--module-inventory FILE` with `preview-modular-pdos` or `export-modular-profile`. Supply `--slot` to compare explicit choices. Without it, a complete detected `0xF050` list supplies fixed-slot choices. Configured `0xF030` evidence stays distinct and cannot supply detected placements. Review the input hash, reported serial and slot differences. A detected conflict blocks profile export. An optional fixed slot can be explicitly empty with `--slot INDEX=0` or a zero at the matching position in a complete detected list. Use `--scenario vacant-middle-slot` with `samples/optional-fixed-slot-pdos.esi.xml` to rehearse this case. Use `--scenario grouped-fixed-slots` with `samples/grouped-fixed-slot-pdos.esi.xml` for declared group increments and per-slot overrides. Use `--scenario repeated-fixed-slots` with `samples/repeated-fixed-slot-pdos.esi.xml` to rehearse fixed-count repetition. Each expanded position needs a manual choice or a detected entry. Supply `--slot-count DECLARATION=COUNT` for each variable repeatable declaration. The `variable-slot-counts` scenario uses `samples/variable-slot-pdos.esi.xml` with counts `0=0` and `1=2`. Use `--scenario mixed-slot-group-indexes` with `samples/mixed-slot-group-pdos.esi.xml` when reviewing a template that uses both offset bases on separate indexes. Use `--scenario pdo-group-alignment` with `samples/module-pdo-group-alignment.esi.xml` to review device and module group membership, order within each SyncManager and assigned alignment PDOs. Saved readback supplies the profile offsets. A membership, order or padding conflict blocks export.
- Offline data: `decode` (or `--rx`), `stage-rx --set INDEX=VALUE`, `scan-virtual`, `decode-esc`, authored replay/virtual runs. Typed staging prepares profile bytes only. An empty staged image requires explicit zero initialization; existing bytes are preserved. Conflicts/ranges/stale previews must remain visible.
- Output proposal: `plan-output` records the exact profile/target, staged and safe bytes, watchdog/OP limits and stop observation. Keep the digest independently and use `verify-output-plan` to recheck it. Pass `--plan` and `--plan-sha256` to the virtual rehearsal to exercise safe preload and restore, modeled OP deadlines, watchdog status and INIT timing. See the watchdog fault scenarios in `docs/output-staging.md`. Hardware approval remains separate.
- Virtual output rehearsal: stage an authored CoE or SII virtual profile using `stage-rx --set 0=VALUE --out NEW_PROFILE`, then run `rehearse-output NEW_PROFILE [--scenario CASE] [--out NEW.json]`. Review the preload and post-OP WKC, independently read AL state, missing-reply outcome, and INIT confirmation. `modeled_outputs` records the ESC simulation's internal state. A fault can produce evidence and a nonzero exit. The command uses the virtual transport and keeps physical approval separate. See `docs/output-staging.md`.
- Capture/review: `run --report` to a fresh JSON path, `verify-capture`, `compare-runs`, `inspect-pcap`, `read-shared` and `inspect-shared`. Follow each guide's supported formats and bounds. For PCAPNG with multiple descriptors, explicitly select `inspect-pcap --interface ID` (0–31); the desktop has the same choice. Selected-interface counts/timestamps stay separate, excluded packet counts remain visible and preview indexes refer to the whole file. Declared PCAPNG interface statistics are retained per snapshot; distinguish absent counters from zero, never sum repeated counters or equate them with bus/CSV/consumer loss, and do not treat declared zeros as complete-capture proof. Inspection/review JSON is not a new run report. Use fresh output paths and keep vendor/private files and raw captures under ignored `.local/`.
- Host prerequisites: `check-runtime [--out NEW.json]` reads installed Npcap DLL headers/literal file versions, local driver-service state and the documented AdminOnly DWORD. It invokes no Npcap exports and performs no NIC enumeration/open or service/registry writes. Inspect observation states and OS errors. A missing policy value is unknown, not false; `present_unprobed` only summarizes headers and service state, and capture access always remains unprobed. See `docs/runtime-check.md`. Existing destinations are preserved. The GUI offers **Device → Host prerequisites… → Check host metadata**, also linked from the isolated bench review. Opening it performs no query; collection and frozen-report/new-file export run as exclusive background jobs. Close/reopen the window without losing results; normal app close waits for a pending host job. `present_unprobed` never enables or approves live operation.
- Virtual DC rehearsal: use `rehearse-dc samples/virtual-dc.json --period-ns 700000 --start-delay-ns 2000123 [--sync1-delay-ns VALUE] [--cycles N] [--scenario CASE] [--out NEW.json]`. Use `--from-esi` in place of explicit timing for a supported staged ESI mode. Review exact-width writes and WKC, activation/period/start, clock and input WKC, deactivation and INIT. Timing is authored and uses an unpaced host loop. See `docs/ethercrab-review.md`.
- Native input: obtain the selected isolated NIC/device/profile and current authorization. Discovery is read-only traffic; SAFEOP initialization is a separate ESC-write scope. Do not infer compatibility or SAFEOP input validity from a byte count or virtual model.

Use `scan-virtual --case two-devices` to exercise read-only bus ordering and per-device audits. The `second-device-diagnostics-timeout` case retains both core reports. The `second-device-core-timeout` case fails discovery at zero-based position 1. Cyclic SAFEOP setup requires one isolated SubDevice.

Use `inspect-input-group samples/input-group.json` to plan one byte-aligned input read from ordered, exact-identity profile references. The report includes position, source profile SHA-256, byte offset and expected LRD WKC; a zero-length TxPDO contributes no bytes or WKC. Supply both `--hex` and `--wkc` for offline typed decoding, and choose a new path for optional `--out`. Keep supplied bytes and WKC separate from identity, mapping and AL evidence. See `docs/input-group.md`.

Use `inspect-input-group MANIFEST --frame FILE` for a saved single Workbench reply. The file declares the expected datagram index, unique station addresses in bus order and raw Ethernet reply hex. Check `frame.valid` and each device's `al` record even when the command succeeds. WKC mismatches, missing AL reads or unclean SAFEOP withhold all decoded inputs. Treat the declaration and reply as offline evidence. `--frame` cannot be combined with `--hex` and `--wkc`.

Add `--fmmu FILE` for a saved per-station channel count and ordered 16-byte FMMU records with WKC. Input mappings must cover exactly the planned byte slices. With `--frame`, check both `frame.valid` and `fmmu.valid`. The same station order, full register coverage and matching geometry are necessary for decoding. Use snapshots from the same setup; these are offline checks and do not verify physical PDO assignments or freshness.

Add `--sync-managers FILE` with `--fmmu` to also check the physical coverage of the enabled buffered input windows. Include the supported-channel count and all eight-byte slots with WKC. When also supplying a frame, check `frame.valid`, `fmmu.valid` and `sync_managers.valid`. The ranges cover each visible first buffer. Keep actual PDO assignments, snapshot freshness and ESC-specific allocation separate.

Add `--pdo FILE` with the FMMU and SyncManager snapshots to compare each station's saved TxPDO layout. The file requires exact declared identity and an explicit CoE or SII layout source. The audit verifies referenced fields, full assignments when the profile has an ESI PDO selection, and logical placement through the FMMUs. Manual fields remain manual. Check `pdo.valid` alongside the frame, FMMU and SyncManager results. These are saved evidence checks.

Use `replay-input-group MANIFEST FIXTURE --csv NEW.csv [--out NEW.json]` to replay the authored group sequence or a supplied fixture. Use `--on-change` for selected-field changes and `--rotate-rows` for numbered parts. Preserve the supplied UTC anchor, elapsed receive offsets and generation/cycle indexes. CSV includes only valid group cycles. The receipt keeps unmatched candidates, WKC and AL quality, saved-clock spacing and writer losses. Schema 4 through 7 fixtures require the raw FMMU/SyncManager replies and surrounding topology probes for each connection generation. Replay rebuilds and checks both before it creates CSV. Any separately supplied FMMU or SyncManager snapshots must match the recorded register evidence. Use `--pdo FILE` by itself with schema 4 through 7 fixtures to check a saved PDO snapshot or complete virtual readback report against the recorded setup of every generation. Reuse that same file when auditing or bundling and review `verified_pdo_generations`. For a complete virtual report, audit also rebuilds the PDO snapshot from its saved setup and requests and replies, and reports `verified_pdo_exchanges`. Fixtures without setup register replies require the separate FMMU and SyncManager snapshots.

Use `verify-group-replay MANIFEST FIXTURE RECEIPT CSV_BASE [--out NEW.json]` with the original references and any mapping evidence used for capture. The command checks the rebuilt cycles, selected rows, typed values and part hashes. Read `complete` and the expected/written row counts. A matching prefix can coexist with a reported writer error. Preserve original evidence and write audit JSON to a new path.

Use `inspect-virtual-group-mapping samples/input-group.json [--scenario SCENARIO] [--out NEW.json]` to check station count, position-based addresses and FMMU/SyncManager readback on the virtual chain. Check `inspection.topology` for the raw before/after replies and per-position WKC, and review overall `valid` even when the command exits successfully. Add `--read-pdos` to read SII identity and CoE or SII TxPDO descriptors after topology and register checks pass. The report adds `pdo_exchanges` and a schema 1 `pdo_snapshot`. Use `coe-pdo-order` or `sii-pdo-order` with the flag to check equal-size descriptor changes. The nested schema 1 snapshots can feed the existing saved-evidence checks. The virtual replay generator gates LRD traffic on topology and register layout checks.

Use `rehearse-group-dc samples/input-group-dc.json [--period-ns N] [--difference-limit-ns N] [--cycles N] [--scenario CASE] [--out NEW.json]` to verify distribution and per-station clock readback before collecting grouped input on two virtual DC stations. Use `samples/input-group-dc-three.json` with the same commands for two followers, including a no-PDO station. `middle-follower-stale` targets that station. Use `topology-change` with the same three-station profile to verify ordered stations in the PDO frame after the clocks pass. It defaults to eight cycles, logs cycles one and three, and requires fresh setup after an observed swap. Use `topology-reconnect` to rehearse two setups, separate SYNC0 verification and delayed input after a first-cycle clock fault in the second generation. Review `clock_rejections`, `valid_input_cycles`, per-cycle `clock.issues` and `cyclic_topology`. The period advances authored fixture time. See `docs/input-group.md`.

Use `generate-group-dc-replay samples/input-group-dc.json [--scenario CASE] [--period-ns N] [--difference-limit-ns N] [--cycles N] --out NEW.json` to save raw clock and input replies. Run `replay-input-group`, `verify-group-replay` and optionally `bundle-group-replay` with that fixture and manifest. Check `counts.clock_rejections`, each cycle's `clock.issues` and spacing. Clock-rejected cycles never reach CSV. See `docs/input-group.md`.

Use `generate-group-replay samples/input-group.json --scenario clean|faults|topology-change [--read-pdos] --out NEW.json` to produce replies from the two in-memory devices. Use `samples/input-group-three.json` with the same scenarios for the three-station chain. Its no-PDO middle station counts in topology and AL validation, and the expected LRD WKC remains two. With `--read-pdos`, schema 7 embeds the raw PDO setup exchanges for every generation. Replay rebuilds both layouts and checks every transcript before CSV creation. Use `verified_pdo_generations` and `verified_pdo_exchanges` in the audit. Replay, audit and bundle either fixture with its original manifest. The `virtual_scenario` marker and scheduled timestamps identify the virtual evidence. In the monitored schema 5 scenario, a topology mismatch latches that generation and withholds cyclic input until a fresh setup passes.

Use `bundle-group-replay MANIFEST FIXTURE RECEIPT CSV_BASE --out NEW_DIRECTORY` with the same mapping options to archive the specifically audited inputs. `verify-group-bundle DIRECTORY [--out NEW.json]` uses bundle-local copies and reruns the audit, including after relocation. Read the completion and row counts. With schema 4 through 7 fixtures the audit includes `verified_topology_generations` and `verified_mapping_generations`. Schema 6 also reports `verified_clock_setup_generations`. Schema 7 reports the PDO setup and exchange counts from the fixture itself. Schema 3 verifies topology, and existing schema 1 and 2 fixtures use their previous rules. Original manifest and receipt bytes retain the supplied path strings.

Use headless files/CLI by default. Desktop input, screenshots or recording need an explicit request in the current chat. Do not run the verification script's optional native GUI mode automatically.

## Desktop navigation

In **Review → Grouped capture**, enter a folder created by `bundle-group-replay` and choose **Verify grouped capture**. The worker verifies the copied evidence and shows verified rows, saved timing and clock/WKC/AL quality. **Cycle details** starts with **Only problem cycles**. **Verified source** retains the opened folder and receipt hash and shows whether setup topology and raw mapping were verified. A fresh **New review JSON** path exports the rebuilt replay details without editing the source bundle. See `docs/desktop-review.md`.

Use `powershell -NoProfile -File tools/rehearse-bench.ps1 -Output .local/rehearsal` with a new directory to practice the virtual CoE scheduler comparison and evidence workflow. Use `docs/bench-qualification.md` to record the actual target, independent input observation and agreed SAFEOP scope when the bench is selected.

In **Saved comparison**, expand **Source files and evidence export** and choose **Check source hashes**, or use `check-comparison FILE [--base DIRECTORY] [--out NEW.json]` to match source bytes to saved hashes. Use the original working folder for relative paths. CLI success means the check completed. Read `all_match`, each file status and `csv_hashes_recorded` for the outcome and coverage. A new comparison performs a fresh audit.

In the same section, enter a new folder and choose **Export evidence bundle**, or use `bundle-comparison FILE [--base DIRECTORY] --out NEW_DIRECTORY`. Both copy verified evidence and retain the original comparison. A readable `bundle.json` marks completion. To verify and reopen a moved bundle, expand **Open evidence bundle** in **Saved comparison** and enter its folder. The CLI equivalent is `verify-bundle DIRECTORY`, which exits with an error for an incomplete or changed bundle. For a fresh comparison bound to the bundle evidence, choose **Recompare bundled trials** or use `compare-runs --bundle DIRECTORY [--out NEW.json]`.

Add `--out NEW.json` to `compare-runs` to save its JSON result. **Review → Saved comparison** opens desktop or CLI exports and identifies the saved bytes by SHA-256. Treat its values and audit status as recorded evidence. Run a fresh comparison to check the original files again.

Run a completed desktop trial set headlessly with `compare-runs --trial-set FILE`. This mode uses the saved report order, CSV path references and `audit_csv` choice. Resolve incomplete rows before comparing. Use explicit report paths and optional `--csv` bases for the alternate CLI mode.

Use **Review → Run reports and CSV → Trial set files** to save or reopen a schema 1 ordered trial list, including partial rows and the CSV-audit option. Save to a new JSON path. Confirm replacement of populated rows or a changed audit option. Relative references follow the set's directory. Keep reports and CSV parts available for a separate **Compare saved trials** action.

Add a saved desktop or audited capture pair to the scheduler comparison from **Logging**, **Diagnostics**, or its completed **Review** result. Existing partial rows stay in place. Arrange trials in capture-start order, leave CSV audits enabled when comparing saved bytes, and let the comparison worker check compatibility. CSV structure passing alone does not qualify a timing trial.

After an acquisition with CSV finishes, **Logging** or **Diagnostics → Save report and audit** uses the completed report and its original CSV base. Once the report is saved, **Audit saved capture** opens the saved pair on the existing review worker. Review inputs and file hashes identify the evidence checked. Manual trial rows remain available for older captures and comparisons.

**Profiles…** shows the loaded/saved source and separate load and create-new save paths. Unsaved settings are marked in the header. Resolve the save, discard, or cancel prompt when loading a profile, opening the offline demo, or closing. Apply offline edits to the working profile before saving. CSV destination and duration are session settings.

Follow `docs/desktop-workspace.md`: Device → ESI/profile or offline demo → Mappings → Logging → Connect/review → Inputs. Profiles and offline decoder use separate windows; raw bytes, rotation/buffers and cycle settings expand. Outputs stages bytes offline only. Integration holds optional feeds; Diagnostics holds timing/device evidence and report saves; Review has separate reports/CSV, comparison, PCAP, saved-snapshot and grouped-capture pages. The SAFEOP plan separates configured identity/image/capture settings from device observations and keeps acknowledgement/start below scrolling details. Acknowledgement binds effective profile/duration/CSV/discovery scope and resets on changes, NIC refresh or scans. Only successful physical results from the selected NIC inform topology preflight; virtual, failed and other-NIC results are distinct and never qualify hardware. The backend independently verifies current bus evidence. Persistent stop/flush and file cancellation survive tab changes. CSV must be configured before the session; Record CSV navigates to setup/status, and Stop and flush ends acquisition as well as draining CSV. Editing is locked during session/discovery/file work. Headless layout tests do not establish native usability.

## Evidence and authorization

The requested 1 ms period is a bench target, not a real-time guarantee. Keep host send/all-reply/valid-input spacing, device/DC settings and capture-clock evidence separate. Reports from 0.31 add optional `valid_receive_spacing`: count is max(valid-1,0), unchanged valid inputs count even with on-change logging, and bad WKC/AL/timeouts stretch gaps between valid inputs. Null/absent metadata is unavailable; a measured count of zero has null percentiles, not zero timing. Comparison valid-input p99 ranges require values from every trial in the scheduler group; inspect `valid_receive_trials` and retain incomplete groups as unavailable. Optional synchronization.coe_cycle readback records setup-only cycle/minimum values for exact CoE objects, in nanoseconds; missing/aborted values are unavailable, explicit zero stays zero, and no host period or sampling-rate guarantee is inferred. These uploads add no cyclic mailbox work or timing downloads. Retain WKC/AL quality, last-valid age, generation/cycle/sample indexes, timeouts, missed deadlines and CSV overruns independently. Every-valid logging includes unchanged values; on-change compares selected bits. Do not report stale/invalid decoded data as current valid input.

Before a physical SAFEOP run, review the exact target and approval for EtherCrab ESC initialization, SM/FMMU configuration from the existing mapping, SAFEOP entry and confirmed INIT cleanup. Only then use `--approve-esc-writes`; the flag is not permission by itself. Honor existing current-session approval for that same scope. Physical OP, PDO downloads, live outputs and enabling DC remain separately approval-gated and await hardware implementation. An installed skill, staged profile or passing offline test grants no hardware permission. Do not retry ambiguous writes automatically.

Use `VERIFICATION.md` and the current chat to identify what was actually tested. Virtual normal/segmented uploads do not resolve EtherCrab's earlier expedited-only private initializer gap. The init-normal-upload and init-segmented-upload virtual faults intentionally fail at that earlier mapping stage and retain an authored injection receipt with INIT cleanup; their expected nonzero exit is a compatibility test, not a hardware diagnosis or fix. Physical device/ESI/NIC selection and an agreed GUI-plus-logger run remain necessary for bench qualification.

The opt-in read-only loopback HTTP feed is documented in `docs/http-input-feed.md`: enable it in the profile or with `run --http-port`, check stream identity/freshness and keep API event indexes/losses separate from CSV and bus quality. It has no output/configuration routes and grants no hardware permission. The opt-in publish-only local MQTT feed is documented in `docs/mqtt-input-feed.md`: check stream/broker-attempt identity, freshness, coalescing and independent errors; QoS 0 TCP writes do not prove delivery. The Windows shared-memory input is documented in `docs/shared-input-feed.md`: open existing read-only objects, copy under the mutex, check QPC/sample age and process creation identity, discard abandoned reads and close retained handles before restart. Use `docs/shared-input-review.md` for native one-shot reads and saved snapshots: optional typed decoding requires the exact effective profile hash (`--profile` or `--run-report`), busy/abandoned input yields no copy, and saved bytes never become current usable input. The desktop saved-snapshot panel in `docs/desktop-review.md` uses the same historical decoder and one cancellable file worker, with raw/current-frozen-profile/saved-run choices and explicit new-file JSON export. Coding/headless layout checks do not authorize native desktop interaction. Its C-readable byte header is not an embedding/function ABI. Optional C ABI/C# embedding remains a roadmap item in `docs/interfaces-roadmap.md`. Do not invent endpoints or copy EtherNet/IP semantics. Maintain the app documentation and skill when implementation changes.
